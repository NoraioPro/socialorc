## B. Per-feature notes and first wall

**/dashboard.** `dashboard/page.tsx:20-37` runs five `post.count` calls plus one `findMany` for the latest 5 posts. XP is `drafts*10 + pending*20 + scheduled*40 + published*100` (`:44`), rank is `floor(xp/250)+1` (`:45`), and the quests are static (`:47-51`). The "AI Content Assistant" card is a string switch on `pendingApproval` with no AI call. *First wall:* none for viewing.

**/dashboard/feed.** It loads 20 posts with 20 comments each (`api/feed/route.ts`). The `where` clause is own posts, or friends' PUBLISHED posts (`:25-30`). The composer calls `POST /api/posts` per platform (`feed/page.tsx:56-61`), which forces `status: DRAFT` (`posts/route.ts:137`). Reaction and comment routes require ownership of the post. *First wall:* the first "Post to timeline" click produces a private DRAFT, and clicking react on any non-own post returns 404.

**/dashboard/inbox.** The client calls `GET /api/inbox` (`inbox/page.tsx:87`). The aggregator fans out per-platform adapters with `Promise.all` and swallows per-adapter errors (`lib/inbox/aggregator.ts:43-59`). Real fetch paths return `[]` (`lib/inbox/adapters.ts`, Twitter `:88`). Reply returns "Not implemented". *First wall:* connecting an account shows "No messages yet" (`inbox/page.tsx:214-218`) forever, and the page cannot distinguish unconnected from unimplemented. The working comment surface is /dashboard/engagement.

**/dashboard/create.** It builds a brief, calls `/api/posts/generate`, edits variants against `PLATFORM_CONFIGS.maxTextLength` (`create/page.tsx:115`), and saves each variant as its own DRAFT. It auto-links the first active account for each platform (`:107-111`). *First wall:* in production without an AI key the API returns 503 (`ai.ts:257`). Instagram, TikTok and YouTube block save without media (`:116`; `platform.ts:492,588,634`). A draft with no connected account fails later with "Post must be linked to a social account" (`schedule/route.ts:50-55`).

**/dashboard/drafts and /drafts/[id].** Lists DRAFT, PENDING_APPROVAL and APPROVED (`drafts/page.tsx:10-27`). Editing resets a post to DRAFT and clears `approvedAt` (`posts/[id]/route.ts:116-121`). PATCH on an APPROVED or SCHEDULED post reverts it to DRAFT but leaves the `ScheduledJob` row PENDING (cron skips it at `cron/publish/route.ts:163`). Publish-now has an atomic claim (`publish/route.ts:169-178`). *First wall:* approval needs ADMIN or MANAGER (`roles.ts:62-72`). An EDITOR sees the Approve button (`drafts/[id]/page.tsx:353`) and gets 403.

**/dashboard/approvals.** Three columns: pending, detail with a checklist, and the next 8 SCHEDULED posts. Approve sets `approvedAt` and `approvedBy` (`approve/route.ts:43-50`). `approve/route.ts:15-19` maps any `action` other than "submit" to approve. *First wall:* the list contains only the viewer's own PENDING posts, so there is no cross-user review queue.

**/dashboard/scheduled, /calendar, /queue.** All three read `Post` and `ScheduledJob`. The only wired schedule-related calls are DELETE `/schedule` (`queue/page.tsx:126`) and PATCH `/reschedule` (`calendar/page.tsx:155`). `ScheduleControl` (`components/posts/schedule-control.tsx`) is imported by nothing. `grep` for it in `src` returns only its own file. *First wall:* no UI creates a SCHEDULED post, so all three pages are empty until `POST /api/posts/[id]/schedule` is called directly, which only the e2e scripts do.

**/dashboard/engagement.** It loads capabilities, then published posts, then comments (`engagement-inbox.tsx:103,117,157`). Tokens are refreshed the same way the worker does (`engagement-api.ts:174-228`) and unrefreshable expiry flags `needsReconnect` (`:181-185`). *First wall:* "Connect an account in Settings to use the inbox." (`:318`), then 503 `PLATFORM_NOT_CONFIGURED` when credentials are missing (`:157-166`), then having no PUBLISHED post with a `platformPostId`. Telegram `listComments` filters on `reply_to_message.message_id` without checking `chat.id`, so one tenant could see another's replies on the shared bot (`telegram.ts:~320`, **per reading**).

**/dashboard/global-map.** It renders 12 fixture regions. The score is `round(growth*0.3 + (1-saturation)*100*0.25 + engagement*0.25 + internetPenetration*100*0.2)` (`lib/global-map/fixtures.ts:297-306`). Thresholds 70/55/40 set the recommendation (`:316-319`). *First wall:* none. It loads instantly with data unrelated to the user.

**/dashboard/ai-studio.** `ai.ts:300-352` asks the model for per-platform JSON variants. Without a key outside production it returns hash-template text (`:143-232`). `ai.ts:265` sets `ctx = brandContext || MOCK_BRAND_CONTEXT`, so the real model receives "SocialOrc Demo Brand" (`types/brand-brain.ts:73`) when the user omits context. `handleSaveDraft` posts only `{content, platform}` (`ai-studio/page.tsx:193-199`), so the mock flag is dropped. *First wall:* in production, 503 "No AI key is configured for this account. Add your own key under Settings -> AI." (`ai.ts:51-53`).

**/dashboard/profile.** It reads the user plus the latest 12 posts and status counts, and edits via a zod schema (`profile/route.ts:6-14`). *First wall:* none.

**/settings/accounts.** It lists platforms with configured and connected state. Disconnect cancels pending jobs and returns SCHEDULED posts to APPROVED (`accounts/route.ts:142-162`). *First wall:* "Needs <ENV VARS>" (`page.tsx:387`), because deployment-level provider credentials must exist first. Then the redirect URI must equal `${APP_URL||NEXTAUTH_URL}/api/social/<p>/callback` (`lib/social/approval.ts:24-35`), and it silently becomes `http://localhost:3000` if both env vars are unset.

**/settings/ai.** The user key is stored AES-encrypted and write-only (`credentials/route.ts:167,219`). The dev fallback encryption key is in the repo and refused in production (`encryption.ts:16,29-34`). The workspace-key tab stays disabled because `fetch("/api/workspaces")` (`page.tsx:72`) hits a missing route. *First wall:* none for a personal key.

**/settings/brand-brain.** It saves 14 free-text fields through a zod upsert. The `BrandBrainContext` type declared at `lib/ai.ts:12` is imported only by `tests/unit/brand-brain.test.ts`. *First wall:* none for saving. The saved profile changes nothing downstream.

**Brand-brain library (`src/lib/brain`).** `ingestText` (`ingest.ts:256-308`) handles txt, md, csv, tsv, json and html. PDF and DOCX throw `UnsupportedFileTypeError` (`:21-29`). The default embedding is `localEmbed`, a 256-dimension FNV-1a feature hash named `local-hash-v1` (`embed.ts:17-19,56-73`), with the comment "It is not a semantic model" (`:51`). A real model is used only if `AI_EMBED_MODEL` or `OPENAI_EMBED_MODEL` is set and a key is passed (`embed.ts:129-141`). Search is brute-force JS cosine (`:76-94`) and `retrieve.ts:34-73` adds keyword and pinned-source boosts. Grep for any importer outside `src/lib/brain` returns none. *First wall:* there is no entry point.

**/login and /register.** Login is NextAuth v4 Credentials plus optional Google/Facebook (`auth.ts:92-162`). Register hashes with bcrypt cost 12 (`register/route.ts:56`). The first user becomes ADMIN, later users EDITOR (`roles.ts:12,29-34`). The count-then-create is not atomic (`register/route.ts:61,81`), so two simultaneous first signups could both get ADMIN (**UNVERIFIED** in practice). *First wall:* on an existing deployment, 403 "Registration is invite-only…" (`register/route.ts:70-73`).

**/ and /characters/[slug].** Both are static. The landing CTA leads to `/register`, which is invite-only. The six characters (`characters.ts:17-24`) have no behavior behind them.

**Worker.** It picks up at most 10 PENDING jobs per tick (`cron/publish/route.ts:94-102`) and claims each with an atomic `updateMany where {id, status:PENDING}` (`:111-118`). Retries use MAX_ATTEMPTS 3, backoff 30s×2^(n-1) capped at 15 minutes (`:30-37`). The real spacing is at least 5 minutes because of the cron tick. Issues found by reading:
- `:264,294` call `handleFailure` without `accountId`, so expiry dead-letters never set `needsReconnect` and the reconnect banner (commit 42af4d2) cannot fire for them.
- `grep` for `maxDuration` in `src` returns no hit in the worker; a serial batch with whole-file video buffering can time out and then be reclaimed after 10 minutes (`lease-recovery.ts:39,106`).
- Publish-now takes no lease. A function kill after the claim strands the post in PUBLISHING and recovery cannot see it (`publish/route.ts` claim ~`:178`).
